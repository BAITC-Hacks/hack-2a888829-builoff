# Мои расходы

Веб-прототип для локального учёта личных расходов студента. Пользователь вручную записывает траты, выбирает месяц и сразу видит список операций, общую сумму и распределение расходов по категориям.

Проект решает базовую задачу контроля повседневных расходов без регистрации, банковских интеграций и передачи финансовых данных на сервер: все записи остаются в браузере пользователя.

## Что реализовано

- добавление расхода с суммой, категорией, датой и необязательным описанием;
- проверка обязательных полей, корректности даты и положительного значения суммы;
- просмотр расходов за выбранный календарный месяц;
- автоматический расчёт общей суммы и итогов по категориям;
- объединение категорий без учёта регистра: например, `Еда`, `еда` и `ЕДА` считаются одной категорией;
- удаление отдельной записи с немедленным пересчётом итогов;
- сохранение расходов в `localStorage` и восстановление после обновления страницы;
- безопасное пустое состояние при первом запуске, отсутствии расходов или повреждённых данных в хранилище;
- форматирование всех денежных значений в казахстанских тенге (`KZT`, `₸`);
- адаптивный русскоязычный интерфейс;
- автоматические тесты модели расходов, валидации, хранения, фильтрации и расчётов.

## Как работает решение

1. При открытии приложение загружает сохранённый массив расходов из `localStorage`. По умолчанию выбран текущий локальный месяц.
2. Пользователь вводит сумму, категорию, дату и при необходимости описание.
3. Приложение проверяет данные. Если они корректны, создаётся запись с уникальным идентификатором и сохраняется в браузере.
4. Для выбранного месяца приложение фильтрует общий массив расходов, сортирует записи по дате и вычисляет общий итог.
5. Те же записи группируются по нормализованному названию категории; суммы по категориям вычисляются заново, а не хранятся отдельно.
6. После удаления записи состояние и `localStorage` обновляются, затем список и итоги автоматически пересчитываются.

Расход с датой из другого месяца сохраняется, но появится в списке только после выбора соответствующего месяца.

## Технологии

| Область | Используемые технологии |
| --- | --- |
| Веб-приложение | React, React DOM, TypeScript, Vite |
| Тестирование | Vitest |
| Хранение данных | браузерный `localStorage` |
| Форматирование | стандартные API `Intl.NumberFormat` и `Intl.DateTimeFormat` |
| Идентификаторы | браузерный `crypto.randomUUID()` |

AI-модели, базы данных, внешние API и сторонние сервисы в текущей версии не используются.

## Установка и запуск

### Требования

- Node.js 20.19+ или 22.12+;
- npm;
- современный браузер с поддержкой `localStorage` и `crypto.randomUUID()`.

### Шаги

```bash
git clone https://github.com/BAITC-Hacks/hack-2a888829-builoff.git
cd hack-2a888829-builoff

npm ci

npm run dev
```

После запуска интерфейс доступен по адресу [http://127.0.0.1:3000](http://127.0.0.1:3000).

Порт `3000` должен быть свободен. Остановка dev-сервера выполняется сочетанием `Ctrl+C` в терминале.

## Как проверить решение

### Ручной сценарий для жюри

1. Запустите проект и откройте `http://127.0.0.1:3000`.
2. Выберите один месяц и добавьте три расхода с датами внутри него:

   | Сумма | Категория |
   | ---: | --- |
   | 1500 | Еда |
   | 600 | Транспорт |
   | 900 | Еда |

3. Проверьте, что отображаются три записи, общий итог равен `3 000,00 ₸`, а итоги категорий — `Еда: 2 400,00 ₸` и `Транспорт: 600,00 ₸`.
4. Обновите страницу. Записи и рассчитанные суммы должны сохраниться.
5. Удалите запись `Еда` на `900`. Должны остаться две записи, общий итог `2 100,00 ₸`, `Еда: 1 500,00 ₸`, `Транспорт: 600,00 ₸`.
6. Переключитесь на месяц без расходов: список должен быть пустым, итог — `0,00 ₸`.
7. Вернитесь в исходный месяц: оставшиеся записи и итог `2 100,00 ₸` должны снова отображаться.

Можно также проверить валидацию: пустые обязательные поля, нулевая или отрицательная сумма не должны создавать запись.

## Данные и интеграции

Единственный источник данных — ручной ввод пользователя. Расход имеет следующую структуру:

```ts
interface Expense {
  id: string;
  amount: number;
  category: string;
  date: string;        // YYYY-MM-DD
  description: string;
}
```

Массив расходов хранится в `localStorage` под версионированным ключом `student-expenses:v1`. Отфильтрованные списки, общая сумма и итоги категорий не сохраняются: они вычисляются из актуальных записей.

Сетевых интеграций и backend нет: приложение не отправляет и не хранит пользовательские данные вне браузера.

## Ограничения текущей версии

- данные доступны только в том же браузере, профиле и origin; синхронизации и резервного копирования нет;
- отсутствуют регистрация, авторизация и разделение данных между пользователями;
- серверное хранение и база данных не реализованы;
- поддерживается только одна валюта — KZT, без конвертации;
- категории вводятся свободным текстом; справочника категорий нет;
- существующую запись нельзя редактировать — только удалить и создать заново;
- нет бюджета, графиков, импорта банковских операций и экспорта данных;
- выбранный месяц не сохраняется между перезагрузками;
- повреждённое содержимое `localStorage` не восстанавливается: приложение переходит к пустому состоянию;
- production-deployment в репозитории не настроен.
